# 相机标定与三维感知实验

相机标定、单目毫米测量、点云配准与几何拟合的实现与验证。

每个模块都带**真值对比**：用合成数据或已知尺寸物体做闭环验证，报出实际误差而不是"效果良好"。

## 内容

| 模块 | 内容 | 核心指标 |
|---|---|---|
| **[calibration](calibration/)** | 棋盘格标定 + 单目毫米测量 | 去畸变使测量 RMS **0.563 → 0.065 mm**（8.6 倍）|
| **[pointcloud](pointcloud/)** | 点云预处理 / ICP 配准 / RANSAC 拟合 | 配准精度 **0.01°**；拟合测尺寸误差比包围盒小 **100 倍** |
| **[synthetic_calib](synthetic_calib/)** | 合成标定数据集生成器（含网页界面）| 零噪声时恢复真值至 **1e-4** |

## 安装

```bash
pip install -r requirements.txt
```

Python 3.9+。核心依赖：`opencv-python`、`numpy`、`open3d`、`matplotlib`。
网页界面额外需要 `gradio`（见 [synthetic_calib/space](synthetic_calib/space/)）。

## 一、calibration：标定与毫米测量

### 原理

```
棋盘格图像 → calibrateCamera（内参+畸变）
          → undistort（去畸变）
          → findHomography（像素 → 毫米）
          → warpPerspective（1px = 1mm 正视图）
          → 点两点得到毫米距离 + 误差预算
```

### 实测结果

用同一个棋盘格自身当标尺做闭环验证（9×6 内角点，方格 20 mm）：

| 测量对象 | 真值 | 不去畸变 | 去畸变 |
|---|---|---|---|
| 横向 8 个间距 | 160.00 mm | 160.58 (+0.58) | 160.05 (+0.05) |
| 纵向 5 个间距 | 100.00 mm | 100.55 (+0.55) | 100.11 (+0.11) |
| 相邻 1 格 | 20.00 mm | 20.23 (+0.23) | 20.04 (+0.04) |
| 对角线 | 188.68 mm | 189.44 (+0.76) | 188.70 (+0.03) |
| **RMS 误差** | | **0.5631 mm** | **0.0654 mm** |

**去畸变消除的是系统偏差，不是随机误差。** 不去畸变时四项误差全为正号，说明畸变让画面整体外扩。

误差预算预测 ±0.147 mm，实测均值 +0.057 mm，在预测范围内。

### 用法

```bash
cd calibration

# 1. 标定（data/dataes2 里有 15 张示例图）
python calibrate.py --dir data/dataes2 --pattern 9x6 --square 20

# 2. 自检：用棋盘格已知间距当标尺
python measure.py -i data/dataes2/1.jpg --pattern 9x6 --square 20 \
    --verify --calib data/dataes2/output/camera_params.npz --out results/check

# 3. 交互测量：鼠标点两点报毫米
python measure.py -i data/dataes2/1.jpg --pattern 9x6 --square 20 \
    --calib data/dataes2/output/camera_params.npz
```

`--pattern` 是**内角点数**（格子数减一）。9×6 个格子 → `9x6`。

### 数据质量的影响

同一部手机，拍法不同，标定结果天差地别：

| 项 | 全正面拍（12 张）| 多角度拍（15 张）|
|---|---|---|
| 重投影误差 | 0.453 px（**更低**）| 0.560 px |
| fx | 2884.4（无意义）| **981.0**（对应 66° FOV）|
| k3 | 12.11（完全失控）| 0.67 |

**重投影误差更低的那组，参数却是错的。** 正视图下焦距与距离不可分离，畸变系数也无约束。

> 结论：RMS 只能证明模型与数据自洽，不能证明参数正确。判断标定质量要看**姿态覆盖度**和**参数是否落在合理范围**。

## 二、pointcloud：点云处理

### Day1 预处理

体素下采样、统计滤波、法向估计，每步都报点数变化和耗时。

| 步骤 | 结果 |
|---|---|
| 体素下采样 | voxel = 2×点间距 → 21600 点降到 2650（12.3%），0.9 ms |
| 统计滤波 | 含 200 个注入离群点，检出 173 个（86.5%）|
| 法向估计 | radius = 7 mm，max_nn = 30，1.3 ms |

**法向必须在降采样后估计**：密集点云里相邻点太近，噪声主导，法向会乱翻。

### Day2 配准与对拍验证

用合成数据做闭环：已知真值变换 `T_true`，比较配准结果 `T_est` 的旋转角和平移量。

| 实验 | 设置 | 结果 |
|---|---|---|
| 小初始误差 | 完整重叠，0~15° | ICP 精确恢复，误差 0.01° |
| 部分重叠 | 50% 重叠 + 30°/60mm | 纯 ICP 失败 **16.69°/42.30mm**；FPFH+RANSAC+ICP 成功 **0.01°/0.01mm** |
| 收敛域扫描 | 完整重叠，0~180° | ICP 到 30° 稳定，45° 开始不稳，120° 以上完全失败 |

**ICP 失败的主因不是初始角度大，而是「看到的不全」。** 50% 重叠时，连 0° 初始位姿都对齐不了——源是完整模型，目标是半个扫描件，ICP 会把源整体拉向目标质心。

```bash
cd pointcloud
python synth_data.py                    # 生成测试数据
python day1_basics.py                   # 预处理（--no-vis 只看数字）
python day2_registration.py             # 配准实验
```

### Day3 几何拟合与尺寸测量

| 方法 | 立方体边长（真值 100 mm）| 误差 |
|---|---|---|
| 包围盒 | 107.87 | **+7.87 mm** |
| 1%~99% 分位数 | 103.13 | +3.13 mm |
| **RANSAC 拟合 6 个面取面间距** | 100.07 | **+0.07 mm** |

同一份数据，**包围盒的误差是拟合法的 100 倍**。因为包围盒只取最深/最高的两个点，一个噪声点就能撑大尺寸。

圆柱拟合的对比更直接：

```
半径误差  0.0195 mm   ← 拟合，全部点参与
高度误差  2.0212 mm   ← 取 Z 极值，只有两个点参与
```

同一个物体，两个尺寸的误差差 100 倍。

```bash
cd pointcloud
python day3_fitting.py                  # 三个拟合实验
python look.py                          # 预处理过程可视化
python look.py --preview                # 只出图，不开窗口
```

### 可视化

`look.py` 用高度着色（jet 色带）+ 坐标轴 + 分步展示，让"为什么要预处理"能用眼睛看出来。

`--preview` 模式用离屏渲染出图，不需要显示器。

## 三、synthetic_calib：合成标定数据集

生成**相机参数真值已知**的棋盘格图像，验证标定算法本身。

### 能证明什么 / 不能证明什么

| 能 | 不能 |
|---|---|
| 验证标定代码是否正确 | 得到真实相机的内参 |
| 量化"角点噪声如何影响精度" | 替代实拍标定 |

### 关键结论

零噪声时能精确恢复真值：

```
fx 800.0002 vs 800.0000   误差 0.0000%
cx 320.0002 vs 320.0000   偏差 0.0002 px
RMS = 0.00004 px
```

角点噪声的影响（决定实拍要多小心）：

| 角点噪声 | RMS | fx 误差 | cx 偏差 |
|---|---|---|---|
| 0.0 px | 0.000 | 0.00% | 0.00 px |
| 0.5 px | 0.689 | 0.73% | 7.70 px |
| 2.0 px | 2.756 | 2.81% | 16.44 px |

**主点比焦距敏感约 10 倍。** 这解释了实拍标定里主点常偏离图像中心几十像素——不是算法错，是约束不足。

### 用法

```bash
cd synthetic_calib

# 生成 20 张 + 真值 JSON
python gen_dataset.py -o output/demo -n 20

# 对拍验证
python check_calib.py -d output/demo --use true      # 用无噪真值
python check_calib.py -d output/demo                 # 用模拟检测噪声
python check_calib.py -d output/demo --detect         # 从图像实际检测

# 参数扫描
python sweep.py --what noise --repeats 3
```

### 网页界面

```bash
cd synthetic_calib/space
pip install -r requirements.txt
python app.py
```

浏览器打开 `http://127.0.0.1:7860`。

界面布局：左侧调参（相机 / 标定板 / 采样），右侧显示合成图 + **真值 vs 估计**对比表。
图像退化和随机种子收在"高级"折叠里，一般不用管。

可以做的三件事：

1. 把**角点噪声拖到 0** → 焦距和主点误差都接近 0，说明算法本身正确
2. 拖到 **2.0** → 焦距误差约 2.8%，但主点偏移 16 px，直观看到"主点最难估"
3. 拖 **k1** → 重投影误差几乎不变，说明 RMS 看不出参数设错

## 四、least_squares：最小二乘与 RANSAC 基础

上面两个模块的地基。圆拟合、DLT、配准的粗解，全是线性最小二乘。

| 脚本 | 内容 |
|---|---|
| `test.py` | 直线拟合，验证 `Aᵀr = 0` |
| `lstsq_new.py` | 圆拟合（线性化 + 代数距离 vs 几何距离）|
| `ransac_compare.py` | 离群点数量 vs 拟合误差，对比 lstsq 与 RANSAC |

### 关键结论

同一组数据（1/4 圆弧 + 离群点）：

| 场景 | lstsq 圆心误差 | RANSAC 圆心误差 |
|---|---|---|
| 完整圆 + 4 个离群点 | 15.58 mm | **0.72 mm** |
| 1/4 弧 + 2 个离群点 | 27.80 mm | 17.03 mm（**失效**）|

**RANSAC 的效果依赖几何约束强度。** 视角不足时（只能看到一小段弧），它和普通最小二乘一起失效——因为三点定圆在短弧上几乎共线，最小求解器本身不稳定。

这不是算法缺陷，是**数据信息量不足**。修法是换机位，而不是换算法。

```bash
cd least_squares
python test.py               # 直线拟合
python ransac_compare.py     # 圆拟合 + RANSAC 对比
```

## 技术要点

### 标定

- **亚像素窗口 = 方格像素边长 / 5**。写死 11×11 会在小方格上崩溃（实测 RMS 从 0.055 涨到 1.93）
- **不要因为图多就启用高维畸变模型**。31 张图用 8 参数有理模型会算出 k1=-30、k5=1175
- **姿态覆盖比张数更重要**。全正面拍 31 张，不如多角度拍 15 张

### 点云

- **法向估计必须先降采样**，否则噪声主导
- **ICP 对部分重叠极敏感**，不是角度问题而是重叠率问题
- **极值法（包围盒、Z min/max）对噪声最敏感**，能用拟合就别用极值

### 通用

- **误差预算只能算随机误差，算不出系统偏差**。系统偏差必须靠"和真值对比"发现
- **对称物体（立方体、圆柱）有配准歧义**，转 90°/180° 后外形一致，任何算法都分不清

## 已知限制

| 项 | 说明 |
|---|---|
| 标定数据用手机拍摄 | 分辨率与真实工业相机不同，参数不可直接复用 |
| 方格边长用标称值 | 未用卡尺实测，是残留系统偏差的主要嫌疑 |
| 点云全为合成数据 | 没有真实扫描数据，不能证明对真实噪声的鲁棒性 |
| 圆柱拟合仅支持轴对齐 | 轴任意时需先估轴向（PCA / 法向聚类）|
| A4 交叉验证未完成 | 拍摄分辨率与标定数据不一致 |
